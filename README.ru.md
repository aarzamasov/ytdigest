# yt2text — YouTube-канал в виде текста

Превращает YouTube-канал (или отдельный плейлист, или одно видео) в текстовые транскрипты и
Markdown-дайджесты: скачивает аудио, расшифровывает его локально с помощью Whisper, собирает один Markdown-файл
на плейлист и один общий на весь канал. Повторный запуск экономичен: скачиваются только новые видео и
перезаписываются только изменившиеся дайджесты.

Назначение: получение текстовой версии (медицинских) YouTube-каналов для ручной загрузки в рабочее
пространство LLM (например, Gemini) и работы с ними через запросы.

- Документация на английском языке: [README.md](README.md)
- Карта файлов кодовой базы: [FILES.md](FILES.md)
- Контекстный промпт для ИИ-ассистентов, работающих с репозиторием: [AGENTS.md](AGENTS.md) (`CLAUDE.md` просто импортирует его)

## Постановка задачи

Входные данные: YouTube-канал. Утилита должна:

| #   | Требование                                                                                                                                                                                                                                                                                       |
|-----|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| R1  | Принимать канал в виде URL, `@handle` или `UC…`-идентификатора; **также** принимать URL отдельного плейлиста или отдельного видео, автоматически определяя тип цели, с возможностью принудительно указать тип через флаги.                                                                       |
| R2  | Находить все плейлисты канала и ссылки на все видео в каждом плейлисте; хранить всё в SQLite.                                                                                                                                                                                                    |
| R3  | Обходить плейлисты в порядке их следования на канале и скачивать аудио каждого видео в формате MP3 с помощью настраиваемой команды оболочки, заданной пользователем.                                                                                                                             |
| R4  | Передавать аудио в движок распознавания речи (STT; выбор движка за исполнителем) и получать чистый текст.                                                                                                                                                                                        |
| R5  | Сохранять текст в виде файлов в структуре папок `канал / плейлист / видео`.                                                                                                                                                                                                                      |
| R6  | После каждого плейлиста формировать один Markdown-файл: название плейлиста → для каждого видео его название и ссылка → полный текст.                                                                                                                                                             |
| R7  | После обработки всех плейлистов формировать один Markdown-файл для всего канала с аналогичной структурой.                                                                                                                                                                                        |
| R8  | Также получать список всех видео канала; видео, не входящие ни в один плейлист, обрабатывать отдельной группой после настоящих плейлистов.                                                                                                                                                       |
| R9  | Видео, встречающееся в нескольких плейлистах, скачивать и транскрибировать один раз, а его текст не дублировать в общем дайджесте канала.                                                                                                                                                        |
| R10 | Повторные запуски инкрементальны: скачивать только новые видео и новые плейлисты, пересобирать дайджест только при изменении содержимого.                                                                                                                                                        |
| R11 | Запуски по отдельным плейлистам / видео работают автономно без полной синхронизации канала; добавленное таким образом должно сохраняться при последующих синхронизациях канала.                                                                                                                  |
| R12 | Вывод предназначен для русскоязычного читателя и LLM: русские заголовки разделов, читаемый текст, стабильные ссылки.                                                                                                                                                                             |
| R13 | Транскрипты записываются короткими блоками с тайм-кодами (примерно по 10 с, с выравниванием по границам предложений); в Markdown-дайджестах каждый тайм-код является ссылкой, открывающей видео на нужной секунде, чтобы найденный в тексте фрагмент можно было проверить на YouTube без поиска. |

Всё из этой таблицы выполняется офлайн: `python tests/run_all.py` (около 3 секунд, без сети, без yt-dlp,
без моделей). Подробнее о слоях тестирования и двух опциональных скриптах проверки на живом YouTube см. в разделе [Тестирование](#тестирование).

**Не проверялось вживую.** Код обнаружения на YouTube протестирован на метаданных формата yt-dlp и сохранённых
фикстурах, а не на реальном сайте; первый запуск на реальном канале является первым живым тестом
(`python tests/live_check.py <канал>` делает именно это во временной папке).
Если `sync` не находит плейлисты или видео: `pip install -U yt-dlp`, а если YouTube требует авторизации — укажите
`youtube.cookies_from_browser` в `config.toml`.

## Как это работает

```
run <цель>  =  sync  →  process  →  build

sync     получение метаданных (yt-dlp, без скачивания) и сохранение в SQLite
process  для каждого плейлиста по порядку: для каждого необработанного видео:
         скачать аудио → расшифровать → записать .txt;
         пересобрать дайджест плейлиста, если плейлист изменился
build    пересобрать дайджест всего канала, если что-либо изменилось
```

Три типа целей (определяются по URL автоматически, см. `detect_target`):

| Цель                                                           | Область действия `run`                                                                                                                                              |
|----------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| channel (канал) — `@handle`, `UC…`, URL канала (любая вкладка) | каждый плейлист, каждое видео вне плейлистов, все дайджесты                                                                                                         |
| playlist (плейлист) — `…/playlist?list=PL…`, голый `PL…`       | только этот плейлист; канал-владелец регистрируется автоматически                                                                                                   |
| video (видео) — `watch?v=`, `youtu.be/`, `/shorts/`, `/live/`  | только это видео; помещается в «Без плейлиста», пока полная синхронизация канала не определит его место (YouTube не раскрывает, в каких плейлистах находится видео) |

Практические правила, заложенные в архитектуру:

- **Состояние обработки принадлежит конвейеру.** `sync` только вставляет новые строки и обновляет метаданные; единственное
  изменение статуса, которое он делает — `skipped ↔ pending` (приватное видео стало публичным, стрим завершился и т. п.).
- **Одно видео — один транскрипт.** Файл `.txt` хранится в папке того плейлиста, под которым видео было обработано первым;
  каждый дайджест, упоминающий видео, читает его путь из `videos.transcript_path`.
- **`.txt` — источник данных, ссылки добавляются при рендеринге.** Транскрипты содержат простые префиксы блоков `[HH:MM:SS]`
  (компактно, удобно искать через grep); `build` превращает их в ссылки `youtu.be/<id>?t=<sec>` в Markdown.
  Переключение `output.timestamp_links` или `output.dedupe_in_playlist_files` меняет отпечатки (fingerprints), поэтому
  следующий запуск перезаписывает дайджесты.
- **Дайджесты — чистая функция базы данных.** Они заново генерируются из строк БД и файлов транскриптов;
  отпечатки лишь определяют, требуется ли запись на диск. `build --force` перезаписывает всё.
- **Сбои локализованы.** Видео, завершившееся ошибкой, помечается как `error` и повторяется при последующих запусках вплоть
  до `download.max_attempts`; флаг `--retry-errors` сбрасывает счётчики. Наличие исполняемых файлов и загрузка модели
  проверяются один раз перед первым видео (быстрый сбой при ошибке конфигурации). Прерывание по Ctrl+C безопасно:
  следующий запуск продолжится с места остановки.
- **Ручные добавления сохраняются.** Плейлист или видео, добавленные по собственному URL, помечаются как `manual` и не
  деактивируются и не удаляются при синхронизации канала, даже если на вкладках канала они отсутствуют (например, скрытые видео / unlisted).
- **Удалённые плейлисты сохраняются, но деактивируются** (`playlists.active = 0`): их транскрипты остаются на диске, они
  просто исключаются из дайджестов.

## Быстрый старт

Требуются Python 3.11+ и ffmpeg (`brew install ffmpeg` / `winget install Gyan.FFmpeg`).

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pip install mlx-whisper                                 # только Apple Silicon; затем backend = "mlx_whisper"

python main.py run @channel --limit 3                   # пробный запуск на трёх видео
python main.py run @channel                             # весь канал целиком
python main.py run "https://www.youtube.com/playlist?list=PL…"   # один плейлист
python main.py run "https://youtu.be/…"                 # одно видео
python main.py run "https://youtu.be/…" --redo          # перераспознать одно видео (использует аудио, если есть)
python main.py run "https://youtu.be/…" --redo-audio    # заново скачать аудио и перераспознать одно видео
python main.py status @channel                          # прогресс; также принимает URL видео / плейлиста
python main.py run @channel --retry-errors              # повторить упавшие видео
python main.py build @channel --force                   # пересобрать все дайджесты
python main.py sync @channel                            # только метаданные, ничего не скачивается
```

Флаги `--channel`, `--playlist`, `--video` переопределяют автоопределение; `--channel <URL видео>` означает «весь
канал, которому принадлежит это видео». Каждая команда принимает опции `-c path/to/config.toml` и `-v` (подробный отладочный вывод).

## Конфигурация

Все параметры с комментариями: [config.toml](config.toml). Наиболее важные из них:

| Ключ                              | Назначение                                                                                                                                                                               |
|-----------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `download.command`                | команда оболочки для скачивания аудиофайла; шаблоны `{url} {video_id} {output_dir} {output_template}`; обязательно сохраняйте `-o "{output_template}"`, чтобы результат можно было найти |
| `transcribe.backend` / `model`    | `faster_whisper` или `mlx_whisper`; по умолчанию `large-v3-turbo`                                                                                                                        |
| `transcribe.language`             | `"ru"`; пустая строка → автоопределение языка для каждого видео                                                                                                                          |
| `transcribe.chunk_sec`            | длина блока с тайм-кодом, по умолчанию 10 с; блок закрывается на следующей границе сегмента Whisper, поэтому предложения остаются целыми; `0` = разбивать только по паузам/длине         |
| `transcribe.timestamps`           | `true` (по умолчанию) → каждый блок начинается с `[HH:MM:SS]`; `false` → сплошной текст и никаких ссылок                                                                                 |
| `output.timestamp_links`          | `true` (по умолчанию) → в `.md`-файлах тайм-код является ссылкой на видео на этой секунде                                                                                                |
| `youtube.channel_tabs`            | `["videos"]`; добавьте `"shorts"`, `"streams"`, чтобы скачивать также короткие видео и записи стримов                                                                                    |
| `youtube.cookies_from_browser`    | `"chrome"` и т. д., когда YouTube требует авторизации для получения списка                                                                                                               |
| `download.keep_audio`             | `false` → удалять MP3 после успешной расшифровки                                                                                                                                         |
| `output.dedupe_in_playlist_files` | `true` → в дайджестах плейлистов ставить ссылку вместо повторения текста видео, которое уже было расшифровано в другом плейлисте                                                         |

## Структура данных

```
data/
├── ytt.sqlite3                      каналы, плейлисты, видео, привязки, статусы, отпечатки
├── ytt.log                          DEBUG-лог каждого запуска
└── <Канал>/
    ├── audio/<video_id>.mp3
    ├── transcripts/<Плейлист>/NNN - Title [video_id].txt
    └── output/
        ├── <Плейлист>.md
        └── _ALL.md                  весь канал целиком (загружать в LLM)
```

## Тестирование

```bash
python tests/run_all.py                      # все модули, каждый в своём интерпретаторе; код возврата 1 при ошибке

Опциональные тесты, требующие сети: `python tests/record_fixtures.py <канал>` сохраняет облегчённые реальные ответы yt-dlp в
`tests/fixtures/` (их следует коммитить; тесты парсинга подхватывают их — перезапускайте после обновления yt-dlp);
`python tests/live_check.py <канал> [--transcribe]` проверяет опрос метаданных на живом сайте и, при наличии
флага, скачивает и транскрибирует самое короткое видео канала с помощью модели `tiny` во временную папку.
`.github/workflows/tests.yml` запускает офлайн-набор тестов на Ubuntu, macOS и Windows с Python 3.11 и 3.12,
плюс задачу `quality` на Ubuntu с установленными инструментами разработки.

mypy                                    # статические типы для ytt/ и main.py
coverage run tests/run_all.py && coverage report -m
mutmut run && mutmut results            # мутационное тестирование, ~10 мин; запускать время от времени, не в CI
```

Мутационное тестирование — это проверка честности самого набора тестов: mutmut вносит точечные изменения в код и ожидает
падения хотя бы одного теста. При последнем полном прогоне было сгенерировано 3344 мутации: 2251 уничтожена тестами, 57 не имели
покрывающего теста и 1036 выжило — большинство выживших это изменения строк логов и сообщений справки, однако прогон также указал на
незащищённые границы сравнений в `segments_to_text`, `safe_name` и `detect_target`, для которых теперь добавлены тесты точных границ.

## Ограничения

- YouTube-миксы (`RD…`), «Посмотреть позже» и «Понравившиеся» не имеют канала-владельца и отклоняются.
- Видео, переданное отдельно, не может быть привязано к своему настоящему плейлисту до полной синхронизации канала.
- Плейлисты на вкладке «Плейлисты» канала приписываются этому каналу, даже если они были сохранены с другого
  канала; плейлист остаётся привязанным к тому каналу, под которым был зарегистрирован изначально.
- Очень большие каналы создают огромный файл `_ALL.md`; если он превышает контекстное окно модели, загружайте
  вместо него файлы отдельных плейлистов.
- Файл дайджеста плейлиста, исчезнувшего с канала, остаётся в `output/` без изменений (его содержимое по-прежнему
  валидно); только `_ALL.md` исключает его.
- Миграций схемы БД пока нет: после изменения схемы базы данных удалите `data/ytt.sqlite3`; в этом случае транскрипты
  будут обработаны заново, так как существующие `.txt`-файлы повторно в базу не подтягиваются.
